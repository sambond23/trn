# TRN — Trusted Relay Network


TRN — Trusted Relay Network
Децентрализованная сеть приватности нового поколения
Версия 2.1 (стабильная)

TRN — это открытая, децентрализованная, самоорганизующаяся сеть, которая позволяет обходить цензуру, защищать трафик от прослушивания и сохранять анонимность в интернете. В отличие от классических VPN и Tor, TRN не имеет единого центра, использует динамическую маршрутизацию, многослойное шифрование, фрагментацию данных и обфускацию трафика для максимальной приватности и устойчивости к блокировкам.

Основные возможности
Децентрализованная архитектура — все узлы равноправны, каждый содержит реестр сети и синхронизируется через gossip-протокол.

Динамическая маршрутизация — клиент строит маршрут из произвольного числа узлов (минимум 3), выбирая Entry, Mid и Exit.

Многослойное шифрование — каждый узел расшифровывает только свой слой (луковая маршрутизация), используя ChaCha20-Poly1305.

Безопасный handshake — обмен ключами по X25519 с подписями ed25519, защита от подмены узлов.

Обфускация трафика — поддержка TLS-транспорта (маскировка под HTTPS) для обхода DPI.

Фрагментация и восстановление — по схеме Шамира (порог 2 из 3), повышает устойчивость к потерям пакетов.

Автоматическая балансировка — узлы могут менять роли при превышении нагрузки (Entry/Mid/Exit).

Отказоустойчивость — выход из строя одного узла не нарушает работу сети (клиент перестраивает маршрут).

Кроссплатформенность — работает на Linux, Windows, macOS, можно собирать под любую архитектуру.

Архитектура
Основные компоненты
Узел (Node) — сервер, который может выполнять одну из ролей:

Entry — принимает трафик от клиентов, маскирует их IP, передаёт дальше.

Mid — промежуточный транзитный узел, перешифровывает трафик.

Exit — отправляет очищенный трафик в интернет.

Реестр (Registry) — распределённая база данных всех узлов сети (публичные ключи, геолокация, нагрузка, роль). Синхронизируется через gossip.

Gossip — протокол обмена реестром между узлами (каждые 15 секунд с случайным пиром).

Клиент (Client) — приложение, которое подключается к любому узлу, получает реестр, строит маршрут и отправляет данные.

Протокол TRP — формат пакетов с вектором маршрута, поддержкой фрагментации и мультишифрования.

Как работает маршрутизация
Клиент запрашивает у любого узла реестр сети.

Клиент выбирает Exit по стране (если задано), случайные Entry и Mid.

Клиент генерирует сессионные ключи для каждого узла, шифрует данные слоями в обратном порядке.

Данные передаются по цепочке Entry → Mid → Exit.

Каждый узел расшифровывает свой слой, передаёт дальше.

Exit расшифровывает последний слой, собирает фрагменты (если есть) и отправляет на целевой сервер.

Ответ возвращается по той же цепочке в обратном порядке.

Безопасность
X25519 + ChaCha20-Poly1305 — надёжное шифрование с защитой от атак на эллиптические кривые.

Подписи ed25519 — верификация узлов при handshake, защита от подмены.

Фрагментация по Шамиру — даже если часть пакетов перехвачена, восстановить данные невозможно без порогового количества частей.

Обфускация через TLS — трафик выглядит как обычный HTTPS, не детектируется DPI.

Отсутствие центрального сервера — нет единой точки отказа и контроля.

Установка и сборка
Требования
Go 1.21 или выше

Git (для скачивания зависимостей)

protoc (Protocol Buffers Compiler) для генерации gRPC-кода

Make (опционально, для автоматизации)

Быстрый старт (Linux/macOS/WSL)
bash
# Клонируем репозиторий
git clone https://github.com/yourusername/trn.git
cd trn

# Устанавливаем зависимости
go mod tidy

# Генерируем gRPC код (требуется protoc)
make gen-proto

# Собираем бинарники
make build
Сборка на Windows
cmd
# Через командную строку (cmd) или PowerShell
go build -o bin\trn-node.exe cmd\node\main.go
go build -o bin\trn-client.exe cmd\client\main.go
Или используйте кросс-компиляцию с Linux/macOS:

bash
GOOS=windows GOARCH=amd64 go build -o bin/trn-node.exe cmd/node/main.go
GOOS=windows GOARCH=amd64 go build -o bin/trn-client.exe cmd/client/main.go
Ручная сборка (без make)
bash
# Генерация protobuf
protoc --proto_path=proto --go_out=. --go_opt=paths=source_relative --go-grpc_out=. --go-grpc_opt=paths=source_relative proto/directory.proto

# Сборка узла
go build -o bin/trn-node cmd/node/main.go

# Сборка клиента
go build -o bin/trn-client cmd/client/main.go
Конфигурация
Конфиг узла (configs/node.yaml)
yaml
node_id: 1                     # уникальный идентификатор (если 0, генерируется автоматически)
listen: ":4433"                # UDP/TCP порт для трафика
grpc_listen: ":50051"          # порт для gRPC (для управления и gossip)
transport: "udp"               # "udp" или "tls" (обфускация)
cert_file: "cert.pem"          # TLS сертификат (если transport=tls)
key_file: "key.pem"            # приватный ключ
country: "US"                  # геолокация узла (для выбора Exit по стране)
city: "NY"
exit_addr: "google.com:80"     # целевой адрес для Exit-узла (для тестов)
max_load: 0.8                  # порог нагрузки (для автоматической балансировки)
initial_role: "entry"          # начальная роль (entry, mid, exit, idle)
Конфиг клиента (configs/client.yaml)
yaml
boot_nodes:                    # список известных узлов (для получения реестра)
- "127.0.0.1:50051"
- "192.168.1.10:50051"
  exit_country: "US"             # желаемая страна выхода (если не указана, выбирается случайно)
  transport: "udp"               # "udp" или "tls"
  cert_file: "cert.pem"          # для TLS (опционально)
  key_file: "key.pem"

На Windows:

cmd
trn-node.exe --config=configs\node.yaml
Запуск клиента
bash
# В другом терминале

На Windows:

cmd

После запуска клиент выведет сообщение и будет ждать ввода текста. Введите любую строку — она будет зашифрована и отправлена через сеть. Ответ от целевого сервера отобразится в логах Exit-узла.

Пример использования
Запустите узел (на своём сервере или локально).

Запустите клиент с указанием boot_nodes (адрес gRPC-порта узла).

Клиент загрузит реестр, выберет Exit (например, в США) и построит маршрут.

Введите сообщение — оно будет передано по цепочке узлов и достигнет целевого сервера.

Если целевой сервер отвечает, ответ вернётся по той же цепочке обратно.

Для проверки можно запустить несколько узлов на разных портах (с разными node_id и listen/grpc_listen). Узлы автоматически обнаружат друг друга через gossip.

Устранение неполадок
Ошибка no boot nodes
Проверьте, что в client.yaml правильно указан список boot_nodes (с дефисами и пробелами).

Запускайте клиент с абсолютным путём к конфигу: --config=C:\полный\путь\client.yaml.

Проверьте кодировку файла (должен быть UTF-8 без BOM).

Ошибка connection refused
Убедитесь, что узел запущен и слушает на указанном порту (grpc_listen).

Проверьте брандмауэр (откройте порты 50051 для gRPC и 4433 для UDP).

Ошибка cannot find package
Выполните go mod tidy и make gen-proto.

Клиент закрывается сразу после запуска
Запускайте из командной строки, чтобы увидеть ошибку.

Используйте .bat файл с pause для удержания окна.
